What it is

You have machines. They sit idle 95% of the time. harness installs as a single binary on each, finds its peers on your LAN, agrees on a brain, and accepts typed task submissions from any of them.

🧠

Local-first brain

The planner runs on a local LLM by default. Cloud (Claude / GPT / Gemini) is escalation, requires policy approval, surfaces the cost.

🎯

Cardinality-aware routing

Every capability declares Anyone / Owner / Federated. The dispatcher enforces it — scoped work lands where the data is, search fans out, stateless jobs go anywhere.

📈

N×X scaling

Streaming dispatch (no full materialization), bounded channels (backpressure tested), resource-aware scheduling, checkpoint/resume, batched local inference, real-time cost tracking.

🔐

Trust-by-default mesh

QUIC + mutual cert pinning. Ed25519 identity per node. Pairing codes for first join. peers.toml on disk. No CA, no IdP, no third party.

💸

Cost is a first-class citizen

Every cloud call has a budget; every plan has a soft + hard limit. Realtime spend graph (Phase 5) and a big red stop button.

📦

One binary. Single file DB.

~30 MB stripped, cross-compiled for {linux, macos, windows} × {x86_64, aarch64}. SQLite + WAL at ~/.harness/harness.db. No broker, no message bus, no external DB server.

Why does this exist?

The default for “an AI workflow” today is to send your data to someone else’s GPU. harness is the bet that a small mesh of your own machines is a real alternative for the 80% of tasks that don’t need GPT-4-class capability — and that for the 20% that do, you should still control the routing, the cost, and the audit log.

Three properties are load-bearing and will not be weakened: local-first planner, first-class capability cardinality, and N×X scaling. Everything else is up for discussion in a PRD-grade ADR.

How it’s built

Strict Rust workspace, 11 crates, one binary. SvelteKit + Tailwind for the embedded web UI (rust-embed at compile time). 410+ tests, 100% on macOS + Linux CI.

Roadmap

Each phase ends with a working, demoable artifact. No phase advances until its demo is reproducible on real hardware. Tests in CI are necessary; the demo is the gate.

shipped phase 0–1
Mesh skeleton
Two laptops discover, sign, elect a brain, reweight under churn.
shipped phase 2
Tasks flow
Submit echo from CLI / UI, persist, list, replicate state.
next phase 3
Fleet exec + brain
harness run --all, local LLM planner, MCP proxy, federated search.
soon phase 4
Distribution patterns
Fan-out controller, DAG executor, resource-aware scheduler, partial streams.
soon phase 5
Planner + cost + external
WhatsApp / SMS / iOS Shortcuts, budgets, checkpoint resume, audit log.
launch phase 6
Hardening + installers
curl|sh + Homebrew tap, signed binaries, self-updater, mobile-responsive UI.
