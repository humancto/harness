# ADR-0035 — iOS Shortcuts adapter (signed JSON token) (5.7)

**Status:** Accepted (2026-08-23)
**Context:** Roadmap 5.7, PRD §20.2 ("iOS Shortcuts (signed JSON
token)"). Unlike the Twilio channels (ADR-0033/0034) there is no
provider in the middle: the phone talks straight to the mesh, so the
"provider signature" is a bearer credential the operator mints.

## What ships

1. **Token scheme** (`harness_vault::shortcuts_token`, zero new
   external deps): `base64url(payload) "." base64url(mac)` with
   `mac = blake3::keyed_hash(key, payload_bytes)` over a compact JSON
   payload `{v, sub, iat, exp?}`. Deliberately **not JWT**: one fixed
   MAC, no header, no `alg` field — the algorithm-confusion surface
   does not exist. The verifier MACs and parses the exact transported
   bytes (no canonicalization round-trip); comparison is
   constant-time (`blake3::Hash` `PartialEq`); strict
   `URL_SAFE_NO_PAD` decoding rejects standard-alphabet or padded
   re-encodings; tokens are length-capped before decoding; `sub` is
   1..=64 printable ASCII at mint AND verify (log-line-injection
   guard).
2. **`POST /webhook/shortcuts`** — `Authorization: Bearer <token>`
   (header only, never a query param), JSON body
   `{goal, request_id?, wait_ms?}` with `deny_unknown_fields` (a
   `constraints` field is a 400, not a silent drop). Fail-closed:
   missing OR malformed signing key → 503. Admission gate + the
   shared 16-permit driver semaphore (429 busy). Mints `brain.plan`
   tagged `[webhook, shortcuts]` (never `cloud_ok`) via the shared
   `mint_task`, then the shared conversation driver
   (plan → `plan.execute` [same tags] → reply text).
3. **Synchronous wait** — Shortcuts is a request/response client, so
   the handler awaits the driver up to `wait_ms` (default 55 s,
   clamped 1–120 s; Shortcuts' own HTTP timeout is ~60 s) and returns
   `200 {task_id, status: done|failed, reply}`. Timeout →
   `202 running` + task id. The permit rides the spawned driver: a
   client disconnect drops only the handler future; work continues to
   the driver's 600 s deadline and the outcome still lands for the
   poll below.
4. **`ShortcutsLedger`** — bounded in-memory maps on
   `WebhookRuntime`: `task_id → outcome` (FIFO 256) and
   `request_id → task_id` (FIFO 512). It serves three roles at once:
   - **Late results:** `GET /webhook/shortcuts/result/:id` (same
     Bearer auth) reads ONLY the ledger — the reply string is
     driver-local and the store has no plan→exec linkage, so the
     ledger is the one honest source.
   - **Authorization scope:** ids absent from the ledger 404 —
     a shortcut token (the lowest-privilege credential in the
     system) can never probe tasks minted by admins, plans, or the
     Twilio adapters, UUIDv7 predictability notwithstanding.
   - **Retry dedup:** a repeated `request_id` returns the ORIGINAL
     task's current status **including its task_id** — the client
     that timed out before seeing the first response can still reach
     its result. Separate from `SeenSids` on purpose: a looping
     authorized Shortcut must not churn Twilio SIDs out of their
     retry-dedup ring.
5. **CLI issuance** — `harness admin issue-shortcut-token --sub
   <label> [--ttl-days N|--no-expiry] [--root]`. Opens the encrypted
   vault locally (the vault key derives from the node identity — no
   daemon needed), reuses an existing signing key (env override
   included, same precedence the daemon reads with) or **generates
   and persists one on first use** via the new atomic
   `EncryptedStore::upsert` (tmp file + fsync + rename, 0600 — a
   crash mid-write cannot corrupt `secrets.enc`; file-origin values
   only, env overrides never bleed into the file).

## Decisions

- **Revocation is key rotation** (replace the vault value): coarse —
  it revokes every token at once — which is why `--ttl-days`
  **defaults to 90** and no-expiry is an explicit flag.
- **`sub` is an audit label, not an allowlist key.** Holding a
  validly-signed token IS the authorization. Per-sub revocation would
  need a denylist; out of scope until someone needs it.
- **Daemon vault staleness is real:** the daemon reads the vault once
  at startup. A key generated by CLI issuance while the daemon runs
  is invisible until restart — the CLI output says so explicitly
  (escape hatch: `HARNESS_SECRET_SHORTCUTS_SIGNING_KEY` in the
  daemon's environment). CLI↔daemon write races on `secrets.enc` are
  accepted for single-operator issuance; the daemon only writes
  during the one-time plaintext migration.
- **Replies inherit the 1600-char cap** on failure diagnostics (the
  truncation lives in the shared driver middle) — fine for a
  Show-Result dialog, one fewer knob.
- **TLS posture is STRICTER than ADR-0033:** a Twilio signature is
  per-request; this token is a static bearer — one plaintext-HTTP
  sniff off-LAN = full access until rotation. Off-host exposure
  without TLS termination is unsupported, full stop.
- **No restart durability** for in-flight conversations or the
  ledger (in-memory, like the Twilio drivers) — same deferral to
  5.11 recorded in ADR-0033 §6.

## Post-open review hardening (#58 Codex + diff review)

- **Atomic dedup:** duplicate lookup → admission → mint → ledger
  reservation run under ONE ledger lock (sync `admit_goal`), so
  concurrent retries with the same `request_id` serialize — exactly
  one mints. A remembered id whose outcome aged out of the ledger is
  an **expired duplicate** (410 + original task id), never a
  re-mint.
- **Bounded in bytes, not just entries:** `request_id` ≤ 128
  printable ASCII, `goal` ≤ 4096 chars — an authorized client cannot
  pin megabyte strings into the ledger or the store.
- **Clock failure fails closed** (503): expiry is never evaluated
  against a zeroed clock. `Bearer` scheme matching is
  case-insensitive per RFC 7235.

## Production cutover

No external account exists for this adapter — the tests exercise the
real token scheme. Going live is entirely operator-side:

1. `harness admin issue-shortcut-token --sub my-phone` (restart the
   daemon if it generated a new key).
2. Build the Shortcut: **Text** (or Dictate Text) → **Get Contents
   of URL** — POST `http://<node>:19198/webhook/shortcuts`, header
   `Authorization: Bearer <token>`, JSON body `{"goal": <Text>}` →
   **Show Result** (the `reply` field).
3. Off-LAN: only behind TLS termination + `HARNESS_WEBHOOK_BASE_URL`
   (see ADR-0033's exposure notes, tightened by the TLS decision
   above).
