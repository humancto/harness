- [x] **5.13c-1** Audit replication, part 1 — **peers pin each other's heads, and a same-seq fork is caught**. New `harness.audit` QUIC channel (incl. `channels::known()` and a `peer_net` recv arm — registering the name without a handler accepts the stream and drops it) carrying signed `AuditHead` messages only; V0010 `audit_peer_heads` PK `(node_id, seq)` **append-only** with `ON CONFLICT` as the fork detector, `audit_head_conflicts` keeping both signatures, and the head-push loop. **No heartbeat field**: `Signable::canonical_bytes` re-encodes the DECODED struct, so an added field makes a pre-5.13c node drop the key, re-encode without it, and fail signature verification — the heartbeat channel dies and the peer ages out. That is a wire BREAK, not the addition ADR-0019's `replica_head` was assumed to be. Pin thinning is status-aware (never evict `contradicted`) and keys on `observed_at_ms`, not `seq`, so a flooder cannot push honest history into the tail. A lower-seq head is NOT evidence by itself — the envelope is not `Sequenced`, so treating it as regression makes replay a one-packet permanent defamation of an honest node.
- [ ] **5.13c-2** Audit replication, part 2 — **a pin can be corroborated from entries**. `AuditEntryWire` + `RangeReq`/`Entries` with `req_id` correlation (this mesh has no request/response primitive — `OutboundMsg` is fire-and-forget), `audit_ingest_range`, `audit_verify_range` (a NEW function: `audit_verify_chain`'s `anchor_holds` accepts only seq 1, a stored predecessor, or a truncation marker, so a legitimate partial pull reports `Broken`; the fourth anchor is a pin WE took), `received_at_ms` (a peer's `at_ms` is attacker-chosen and `audit_recent` orders by it), and the pull endpoint reaching the mesh through an injected trait — `harness-api` cannot depend on `harness-daemon`.
- [ ] **5.13c-3** Audit replication, part 3 — operator surface. Per-node coverage in `verify_page`, the UI banner states, conflict acknowledgement (a node may NOT ack a conflict about itself; acks replicate as entries but not as authority; post-ack is amber-with-history, never green), `audit_forget_peer_range` (delete-only and pin-aware — `audit_prune` for a peer would forge a marker row INTO that peer's chain), and **eager background corroboration**: peers prune at 100k, so a pin never corroborated before its owner pruned past it is permanently `unverifiable`, and on a busy node that is every historical pin — the amber banner becomes the steady state, which is ADR-0041 Decision 4's failure by a slower road.
- [ ] **5.13d** Keyed `argv_hash`. Once entries replicate, `argv_hash` is an offline confirmation oracle for low-entropy arguments. Key it with `blake3::derive_key("harness audit argv v1", secret)` — never the raw ed25519 seed — stamped `argv_hash_v: 2`. It is a string inside `detail`, NOT part of the chain preimage, so no existing row's verification changes and no migration is needed. Costs to record: cross-node argv correlation is lost, and an operator investigating from another node can no longer test a candidate argv at all. Repurposing the identity secret as MAC key material is a new secret-handling path and gets a sentence to the user.
